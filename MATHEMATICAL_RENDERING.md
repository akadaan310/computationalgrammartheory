# Mathematical Rendering

**Policy:** no equation may silently fall back to raw LaTeX. Every formula in the book, in the glossary and on the standalone pages is rendered **at build time**. Any parse error, undefined macro or strict-mode warning **fails the build**.

## 1. Engine and configuration

- **Engine:** KaTeX 0.16.22, pinned exactly in `book/package.json`. It is called from `book/tools/build.mjs` (`renderMath`) with these options:

```js
katex.renderToString(tex, { displayMode, throwOnError: true, strict: "error",
                            output: "htmlAndMathml", trust: false, macros })
```

- **`throwOnError: true`.** A parse error throws instead of returning red source text. The build records it as an integrity error, with file, line and the first 80 characters of the formula. The page gets an explicit `[equation failed to render: build error]` alert, and the build exits with status 1, so no such page is ever published.
- **`strict: "error"`.** KaTeX's non-standard-input warnings (for example, Unicode text in math mode) are errors.
- **`output: "htmlAndMathml"`.** Every formula carries visual HTML *and* MathML for screen readers.
- **`trust: false`.** No `\href`, `\includegraphics` or HTML injection from math.
- **No client-side math rendering.** Pages are readable with JavaScript disabled, and nothing reflows after load. The stylesheet `katex.min.css` and its `woff2` fonts are copied into `dist/assets/katex/`, so no CDN is needed.

**Verified (2026-10-08).** I appended `$$\frac{1}{$$` and `$\undefinedmacro{x}$` to the math test page. The build reported both errors with their locations, printed `2 integrity error(s); build FAILED.` and exited 1. The test lines were then removed, and `dist/` contains no `math-error` element.

## 2. Authoring syntax (book sources, `book/content/`)

| Construct | Syntax | Result |
|---|---|---|
| inline math | `$...$` | KaTeX inline |
| display math | `$$...$$`, on its own lines | KaTeX display, horizontally scrollable on narrow screens |
| numbered equation | `\label{eq:name}` inside `$$...$$` | numbered (chapter.k) through `\tag`; cite with `\eqref{eq:name}` |
| aligned derivations | `\begin{aligned} ... \end{aligned}` inside `$$` | |
| cases, matrices | `\begin{cases}`, `\begin{pmatrix}` | |
| project macros | `book/content/macros.json` | 22 macros, below |

Project macros:
- semantics, grammars and structures: `\sem{·}` (⟦·⟧), `\Lang`, `\Str`, `\Rel`, `\then` (relational composition);
- asymptotics and operations: `\Oh`, `\dom`, `\msb`, `\lowbit`, `\addr`, `\cost`, `\indeg`, `\outdeg`, `\cmp`;
- complexity classes: `\poly`, `\Ppoly`, `\P`, `\NP`, `\PH`;
- number sets: `\N`, `\Z`, `\R`.

Use a macro whenever a notion has one, so that notation stays uniform. Appendix A (Notation) lists the meanings.

## 3. Test suite

`book/content/pages/math-tests.md` builds to `math-tests.html`. It renders the formulas the book actually relies on:
- relational semantics;
- aligned contraction proofs;
- nested floors and shifts (THM-006);
- cases;
- matrices;
- sums and products;
- binomials;
- complexity-class notation;
- accents and spacing.

It is part of every build, so a KaTeX upgrade that broke any of them would fail the build.

## 4. Print and PDF

The PDF (`npm run pdf`) prints the same KaTeX HTML through headless Chromium (D-022), so formulas in the PDF are identical to those on the web. In print there is no scrolling, so the stylesheet switches off scroll containers, wraps code blocks, and sets display math at 95 %. Before writing the PDF, `tools/pdf.mjs` lays out `print.html` at the width of the A4 text block (174 mm) and **refuses to produce a PDF** if any equation, table, code block or figure is wider than that, so it cannot be silently clipped. That check found 36 clipped code blocks and one equation that was 5 px too wide in the first PDF; all are fixed. The math test page is a web page and is not part of the print edition.

## 5. Known limitations

- KaTeX does not support every LaTeX package: no `\newenvironment` and no TikZ. Diagrams in the book are SVG or HTML generated by the laboratory, not LaTeX.
- On narrow screens, long display equations scroll horizontally inside their container. They are not broken across lines.
- MathML output depends on browser support for accessibility, and the visual rendering does not depend on it. Screen-reader behaviour has not been tested with assistive-technology users.
